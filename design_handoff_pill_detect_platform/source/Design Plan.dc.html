알약 객체 탐지 실험 플랫폼

이미지 1장당 최대 4개의 알약을 탐지하고 클래스와 bounding box를 예측하는 모델을, 재현 가능하게 학습·비교·진단하기 위한 사내 도구. Training GUI와 Evaluation GUI 두 모듈을 하나의 플랫폼 셸로 묶는다.

01

확정된 전제

FRAMEWORKPyTorch 전체 계열Ultralytics YOLO · torchvision · MMDetection(DINO/RT-DETR)을 모두 하나의 폼에서 다룸 → 모델 패밀리 선택에 따라 하이퍼파라미터 필드가 동적으로 교체됨.
COMPUTE로컬 + Colab실행 대상을 런마다 선택. Colab은 세션 만료라는 고유 실패 모드가 있으므로 재개(resume) 경로와 세션 잔여 시간을 UI에 노출.
TRACKINGWeights & Biasesrun id · project · entity가 모든 실험의 1차 키. 아티팩트/차트는 W&B를 원천으로 하고 GUI는 운영 뷰만 제공(중복 구현 X).
METRICS6종 1급 지표mAP@0.5 · mAP@0.5:0.95 · Precision/Recall/F1 · per-class AP · confusion matrix + IoU 분포 · inference speed(ms, FPS).
KAGGLEMVP 포함 · 전체제출 파일 생성·이력·public LB 점수·일일 잔여 횟수까지. 단 LB 점수를 로컬 validation보다 상위에 두지 않는 배치를 유지.
언어 · 밀도한국어 UI · 밀도 8/10모든 chrome·산문은 한국어, ML 용어는 영문 유지. 테이블 행 높이 34px, 12–13px 본문의 엔지니어링 밀도.
답변받지 못한 항목 — 아래 가정으로 진행합니다 · 클래스/데이터셋: 알약 12개 클래스, train 3,200장 / val 800장, 이미지당 1–4개. 메타데이터로 lighting(자연광/형광등/저조도), background(단색/손바닥/포장재), blur score 보유 가정.
· Kaggle 제출 포맷: image_id,PredictionString — {class} {conf} {xmin} {ymin} {xmax} {ymax} 반복.
· 백엔드 계약: FastAPI REST + WebSocket 로그 스트림, Redis 기반 런 큐 가정.
실제 값을 주시면 목 데이터와 프리뷰를 그대로 교체합니다.
02

엔드투엔드 워크플로우

한 번의 실험 사이클은 설정 → 학습 → 평가 → 진단 → 선택 → 제출이며, 진단 결과가 다음 실험의 설정으로 되돌아오는 닫힌 루프입니다. GUI의 역할은 이 루프를 한 바퀴 도는 데 필요한 수작업(YAML 편집, 폴더 뒤지기, 스크립트 인자 조합)을 없애는 것입니다.

01 CONFIGURE실험 설정데이터셋 버전 · 모델 · HP · augmentation
02 REVIEW설정 검토YAML diff · 경고 · 자원 추정
03 TRAIN학습 실행 · 모니터라이브 곡선 · 로그 · GPU
04 EVALUATE지표 · 비교PR curve · per-class AP · diff
05 DIAGNOSE실패 분석예측 검사기 · 실패 갤러리
06 SELECT임계값 · 체크포인트conf/NMS 튜닝 후 확정
07 SUBMIT제출 · 기록CSV 생성 · LB 점수 회수
FEEDBACK LOOP 05 실패 분석에서 「이 실패 그룹으로 다음 실험 제안」 → 01 설정 화면이 해당 augmentation/HP가 미리 채워진 상태로 열림. 이 링크가 두 GUI를 하나의 제품으로 만드는 핵심입니다.

MODULE BEvaluation GUI
과거를 해석한다. 이미 고정된 결과를 놓고 「왜」를 캐는 도구. 주 산출물은 점수가 아니라 다음 실험의 근거다.
읽기(read) 중심 · 필터와 비교 시간축 = 누적(전체 실험 이력) N개 실험 교차 스코프 실패 = 놓친 알약 · 오분류 · 중복 박스
경계 1 · 임계값학습 HP는 Training에서만 편집 가능. 추론 임계값(conf/NMS/max-det)은 Evaluation에서만 편집. 학습 화면의 임계값 필드는 「validation 중 사용값」으로 명시하고 회색 처리.
경계 2 · 불변성완료된 실험의 config는 Evaluation에서 절대 수정 불가. 바꾸고 싶으면 「실험 복제」로 새 런을 만드는 경로만 존재 — 재현성 보장.
경계 3 · 데이터 누수test split을 validation으로 지정하거나 이전 런과 seed/split이 겹치면 두 모듈 모두에서 amber 경고 배너를 띄우고 제출 생성을 차단.

「새 실험」 레이아웃 — 3개 변형안

하나 골라주시면 그 방향으로 제작합니다
A위저드추천
5단계 순차 진행. 각 단계마다 검증 통과해야 다음으로.
+ 신규 팀원이 실수 없이 완주. 「저장된 config 없이는 실행 불가」 원칙을 구조로 강제. − 숙련자에게 느림. 한 필드만 고쳐 재실행하는 일상 작업에 5클릭.
B단일 페이지추천
전 섹션 세로 스크롤 + 우측 목차 앵커. 접기/펼치기.
+ Ctrl+F로 필드를 찾을 수 있음. 전체 설정을 한눈에 훑기 좋음. − 40+ 필드가 한 페이지에. 생성될 config를 보려면 맨 아래까지 스크롤.
C분할 · 설정 ↔ 라이브 프리뷰추천
좌: 탭 폼 / 우: 실시간 YAML · baseline diff · 경고 · 자원 추정.
+ 「설정과 결과의 분리」 원칙이 화면에 그대로. 재현성·diff·경고가 입력하는 순간 보임. − 폼 폭이 좁아짐. 1440px 미만에서는 프리뷰를 서랍으로 접어야 함.
제 추천은 C(분할)입니다. 브리핑의 핵심 원칙 세 개 — 재현성을 눈에 보이게 / 설정과 결과를 분리 / 저장된 config 없이 실행 금지 — 가 모두 「생성될 config를 실시간으로 보여준다」는 하나의 장치로 해결됩니다. A의 강제 검증은 C 안에 탭별 검증 배지로 흡수하고, B의 훑어보기는 「전체 보기」 토글로 흡수할 수 있습니다. 다르게 보시면 A나 B로 갑니다.

백엔드 통신

# 프론트엔드는 학습 로직을 갖지 않는다. config를 만들고 상태를 읽을 뿐. POST /api/experiments config JSON → run_id 발급 (등록만, 실행 X) POST /api/experiments/:id/validate 서버측 스키마·자원·누수 검사 → warnings[] POST /api/experiments/:id/start 큐 투입. target=local|colab POST /api/experiments/:id/stop GET /api/experiments?status=&owner= GET /api/experiments/:id config + 최종 지표 + 아티팩트 목록 GET /api/experiments/:id/config.yaml GET /api/runs/:id/predictions ?filter=fp,fn,wrong_class&conf=0.25 POST /api/runs/:id/evaluate 임계값 재적용 → P/R/F1 재계산 (캐시) POST /api/submissions CSV 생성 잡 GET /api/gpu/status 폴링 5s WS /ws/runs/:id epoch_end · batch_metrics · log_line · error WS /ws/queue 큐 순서 변경 · 세션 만료 경고
등록과 실행의 분리create → validate → start가 별개 호출. 「저장된 config 없이 런 시작 불가」가 API 수준에서 강제됩니다. 시작 버튼은 validate가 200을 준 뒤에만 활성화.
W&B는 원천, GUI는 뷰학습 스크립트가 W&B에 직접 로깅하고, 백엔드는 wandb_run_url과 요약 지표만 릴레이. 상세 차트는 W&B로 딥링크 — 중복 구현하지 않습니다.
임계값 재계산은 서버에서슬라이더가 움직일 때마다 원시 예측(raw boxes+scores)에 대해 NMS를 다시 돌립니다. 200ms 디바운스 + 결과 캐시. 재학습은 절대 발생하지 않음을 UI에 명시.
Colab 재개세션 만료 시 런은 interrupted 상태로 남고, 마지막 체크포인트에서 「재개」 액션이 노출됩니다. 이어붙인 런은 계보(lineage) 배지로 표시.
